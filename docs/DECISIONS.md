# Журнал рішень

Формат: **ID — рішення.** Чому. Статус перевірки.

## Етап 0

**D-001 — Тимчасовий шаблон пакета взято з колишнього експортера draw.io.**
Бриф (§4, §8) вимагає `template/blank.vsdx`, збережений самим Visio. Поки його немає, `drawio2vsdx/template/blank.vsdx` зібрано скриптом `scripts/build_provisional_template.py` зі скелета, вбудованого у `VsdxExport.js` (jgraph/drawio v24.7.17, Apache-2.0): `[Content_Types].xml`, rels, `docProps/*`, `visio/document.xml` (зі стилями і шрифтами), майстер «Dynamic connector», `windows.xml`. Додано одну порожню сторінку, щоб письменник завжди мав базовий `PageSheet`. Цим скелетом draw.io роками генерував файли, які Visio відкривав.
*Статус:* тимчасово. **Замінити на `blank.vsdx` від автора**, щойно він з'явиться (письменник уже вміє працювати з будь-яким шаблоном: опція `--template`, базовий `PageSheet` береться з першої сторінки шаблону, сторінки/медіа/overrides перегенеровуються).

**D-002 — Масштаб 101.6 px/дюйм.**
`mxVsdxUtils.screenCoordinatesPerCm = 40`, `CENTIMETERS_PER_INCHES = 2.54` (імпортер draw.io) і `VsdxExport.prototype.CONVERSION_FACTOR = 40 * 2.54` (експортер). Отже перевірка «туди й назад» через імпорт draw.io дає ті самі розміри. Опція `--scale`.
*Статус:* підтверджено в коді.

**D-003 — Розмір сторінки Visio = bbox вмісту + 20 px поля; для порожньої сторінки — `pageWidth/pageHeight` моделі.**
Опція `--page-size` вмикає розмір сторінки draw.io (розширений до вмісту, якщо той виходить за межі). Відображення координат зосереджене в `writer/page.py::PageLayout` (X: `(px - origin_x)/scale`, Y: `height - (py - origin_y)/scale`).

**D-004 — Унікальні назви сторінок.**
Visio вимагає унікальних (без урахування регістру) непорожніх назв сторінок, draw.io — ні. Дублікати отримують суфікс ` (2)`, порожні назви — `Page-N`. Валідатор перевіряє це.

**D-005 — `docProps/app.xml`: `HeadingPairs`/`TitlesOfParts` видаляються.**
Visio записує туди список сторінок; застарілий список (від шаблону) гірший, ніж відсутній (елементи необов'язкові). [VERIFY на шаблоні від Visio: чи Visio web не скаржиться.]

**D-006 — Нічого не губиться мовчки навіть на етапі 0.**
Поки фігури не пишуться, кожна непорожня сторінка дає запис `unsupported/not-implemented` у звіті; `--strict` перетворює це на помилку, `--strict-warnings` — на код виходу 2.

**D-007 — Тестова інфраструктура без scikit-image.**
SSIM реалізовано на numpy (вікна 8×8, константи Wang 2004, кадрування до вмісту) у `tests/imgcompare.py`. Менше важких залежностей у `[dev]`.

**D-008 — Пошук рендерерів для тестів:** змінна оточення (`DRAWIO_PATH`, `DRAWIO_ORACLE_PATH`, `SOFFICE_PATH`) → `PATH` → `~/tools/...` (куди ставить `scripts/setup-dev-tools.sh`). Без інструментів render-тести пропускаються, а не падають. На Linux без `DISPLAY` draw.io запускається через `xvfb-run -a`.

**D-009 — Вихідники колишнього експортера.**
У тезі v26.0.16 `VsdxExport.js`/`mxVsdxCanvas2D.js` окремо вже немає (лише у мініфікованому бандлі). Останній тег з вихідниками — **v24.7.17** (`src/main/webapp/js/diagramly/vsdx/`). Там же `importer.js` (JS-порт Java-імпортера).
