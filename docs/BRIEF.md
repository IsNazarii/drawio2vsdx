# drawio2vsdx — бриф проєкту

> Документ для сесій Claude Code. Містить контекст, вимоги, архітектуру, етапи і спосіб перевірки.
> Пункти з позначкою **[VERIFY]** — це припущення, які треба підтвердити на еталонних файлах, а не брати на віру.

---

## 1. Контекст і мета

- draw.io мав вбудований експорт у VSDX (позначений як beta), але **приблизно в березні 2025 його прибрали**. Остання версія з експортом — **draw.io Desktop v26.0.16** (https://github.com/jgraph/drawio-desktop/releases/tag/v26.0.16).
- Окремого відкритого конвертера `.drawio → .vsdx` немає.
- **Мета:** універсальний CLI-інструмент на Python, який конвертує довільні діаграми draw.io у `.vsdx`. Файл має відкриватися у Visio (веб-версія Microsoft 365 і десктоп) без попередження про відновлення і лишатися придатним до редагування: фігури можна рухати, лінії приклеєні, текст редагується.
- **Інструмент універсальний.** Реальні мережеві топології автора — лише головний набір для перевірки, а не межа можливостей. Будь-яка фігура, яку не вдалося відтворити нативно, має потрапити у Visio хоча б як картинка, а не зникнути мовчки.

### Не входить у задачу
- Точна попіксельна відповідність. Мета — «виглядає так само і зручно редагується».
- Старий бінарний `.vsd`, `.vdx`, шаблони `.vssx`/`.vstx`.
- Зворотний напрям Visio → draw.io (draw.io сам вміє імпортувати `.vsdx`).
- Анімація, «розумні» властивості Visio, data graphics.

## 2. Середовище

**Розробка — Ubuntu (Claude Code). Використання — ноутбук на Windows.** Звідси правило: усе, що потрібно для *роботи* інструмента, має працювати на Windows; усе, що потрібно лише для *розробки й тестів*, може бути тільки на Ubuntu.

- Python 3.11+.
- Visio: **веб-версія через Microsoft 365** — основний спосіб ручної перевірки; десктоп — лише за великої потреби (якщо з'явиться на Windows-ноутбуці, ним теж можна перевіряти).

### 2.1 Робоче середовище (Windows)
- Python-залежності для роботи: **лише ті, що мають готові Windows-wheels** (`lxml` — так). Нічого, що треба компілювати.
- **draw.io Desktop для Windows** — потрібен лише для fallback-рендеру іконок (§6.4). Шлях до виконуваного файлу:
  1. опція `--drawio PATH` / змінна оточення `DRAWIO_PATH`;
  2. автопошук: `%ProgramFiles%\draw.io\draw.io.exe`, `%LocalAppData%\Programs\draw.io\draw.io.exe`; на Linux — `drawio` у PATH, flatpak, AppImage;
  3. не знайдено → іконки замінюються підписаною заглушкою + чітке попередження у звіті, а не падіння.
  На Windows `xvfb` не потрібен; на Linux без дисплея — `xvfb-run -a`.
- **Спільний кеш іконок** (`--icon-cache DIR`): відрендерені іконки (ключ — hash стилю й розміру, §6.4) можна заздалегідь згенерувати на Ubuntu і покласти поруч з інструментом. Тоді на Windows для вже відомих іконок draw.io не потрібен узагалі.
- Поставка: два варіанти, обидва описати в README:
  - `pipx install git+https://github.com/<user>/drawio2vsdx` (потрібен Python на ноутбуці);
  - **один `drawio2vsdx.exe`** через PyInstaller. Збирається **лише на Windows** (PyInstaller не збирає крос-платформно), тобто в GitHub Actions на `windows-latest`, і викладається в Releases.
- Зручність (етап 5): `.bat`-обгортка і пункт «Надіслати → drawio2vsdx» у контекстному меню Провідника (скрипт встановлення додає ярлик у `shell:sendto`). Перетягнув `.drawio` — отримав `.vsdx` поруч.

### 2.2 Середовище розробки (Ubuntu)
- **draw.io Desktop (актуальна версія, deb або AppImage)** + `xvfb-run` — fallback-рендер і перевірка «туди й назад» (draw.io вміє імпортувати `.vsdx`).
- **draw.io Desktop v26.0.16 (AppImage)** — **оракул**: його власний VSDX-експорт тих самих фікстур, з яким можна порівнювати свій XML. Тільки для тестів.
- **LibreOffice (headless)** — незалежний рендер `.vsdx → PNG` для автотестів.
- Тестові залежності (`Pillow`, `scikit-image` або аналог для SSIM, `pytest`) — в окремій групі `[dev]`, не в робочих залежностях.
- Без Aspose і подібних комерційних бібліотек.

### 2.3 CI (GitHub Actions)
- `ubuntu-latest`: усі тести, у тому числі рендер LibreOffice, оракул і «туди й назад».
- `windows-latest`: модульні тести + структурні перевірки пакета (§7.1 п.1) + конвертація всіх фікстур **з кешем іконок і без draw.io**, + збірка `.exe` і запуск його на фікстурі. Мета — гарантувати, що на Windows нічого не ламається через шляхи, кодування чи залежності.

## 3. Інтерфейс CLI

```
drawio2vsdx INPUT [-o OUTPUT] [опції]

INPUT                 .drawio / .xml / .drawio.svg / .drawio.png (з вбудованим XML) або тека (з --recursive)
-o, --output          файл .vsdx або тека
--pages all|1,3|Name  які сторінки конвертувати (за замовчуванням усі)
--icons image|vector  як переносити фігури без нативного відповідника (див. §6.4); за замовчуванням image
--image-format png|svg  [VERIFY підтримку SVG у Visio, див. §8]
--dpi N               для растрових іконок (за замовчуванням 192)
--reroute never|asneeded|freely   поведінка ліній у Visio (див. §6.3); за замовчуванням never
--scale F             px → дюйми (за замовчуванням як у VSDX-імпортері draw.io, див. §5)
--report PATH         JSON/MD-звіт про втрачені й наближені елементи
--drawio PATH         шлях до draw.io Desktop для fallback-рендеру (див. §2.1)
--icon-cache DIR      тека кешу відрендерених іконок (спільна між машинами)
--strict              помилка замість попередження на непідтримуваному
-v / -q
```

Код виходу: 0 — успіх; 1 — помилка; 2 — успіх із попередженнями (лише коли задано `--strict-warnings`).

## 4. Архітектура

```
drawio2vsdx/
  cli.py
  reader/
    decode.py        # розпакування: base64 + raw deflate + URL-decode; .drawio.svg/.png з вбудованим XML
    parse.py         # mxGraphModel → IR; <object>/<UserObject> обгортки; шари; абсолютні координати
    style.py         # розбір рядка стилю + ЗНАЧЕННЯ ЗА ЗАМОВЧУВАННЯМ draw.io (див. §6.1)
    label.py         # HTML-підписи → текстові фрагменти з форматуванням (bold/italic/колір/розмір/переноси)
  ir.py              # проміжна модель, незалежна від обох форматів (dataclasses)
  mapping/
    registry.py      # shape-ім'я → обробник (нативний | fallback); розширюваний
    primitives.py    # rect, rounded, ellipse, rhombus, triangle, hexagon, cylinder, cloud, parallelogram, ...
    edges.py
    containers.py    # group, container=1, swimlane
  render/
    fallback.py      # рендер довільної фігури через draw.io CLI → PNG/SVG, з кешем
    stencil2geom.py  # (етап 6) стенсил draw.io → геометрія Visio
  writer/
    package.py       # OPC-пакет: zip, [Content_Types].xml, rels; береться з ШАБЛОНУ
    page.py          # Shapes, Connects, PageSheet
    shape.py         # Cells/Sections: XForm, Line, Fill, Character, Paragraph, Geometry, Connection, Property, Hyperlink
    media.py         # visio/media/*, ForeignData, rels сторінки
  report.py
  template/
    blank.vsdx       # порожній файл, збережений САМИМ Visio (від автора), основа пакета
tests/
  fixtures/features/ # синтетичні: одна можливість — один файл (генерує Claude)
  fixtures/real/     # реальні топології автора (у .gitignore, якщо приватні)
  references/        # еталонні .vsdx, створені у Visio (від автора)
  oracle/            # .vsdx тих самих фікстур, експортовані draw.io v26.0.16
```

**Ключові рішення:**
1. **IR посередині.** Читач і письменник не знають одне про одного. Тестувати можна окремо, а пізніше додати інші вихідні формати.
2. **Пакет — із шаблону.** Не генерувати `.vsdx` з нуля: брати `blank.vsdx`, збережений Visio, і замінювати або додавати лише сторінки, медіа і rels. Так уся службова частина гарантовано валідна.
3. **Реєстр фігур.** Кожен `shape=...` обробляється зареєстрованим обробником. Невідомий → fallback (картинка) + запис у звіт. Нові нативні фігури додаються без змін ядра.
4. **Нічого не губиться мовчки.** Будь-яке спрощення чи втрата фіксується у звіті з id елемента.

## 5. Системи координат

- draw.io: пікселі, вісь Y вниз, початок — лівий верхній кут. `mxGeometry x,y` — **лівий верхній кут** фігури, **відносно батька** (група/контейнер/шар).
- Visio: внутрішні одиниці — **дюйми**, вісь Y **вгору**, початок — лівий нижній кут сторінки. Положення фігури — `PinX/PinY` (точка обертання), зазвичай центр (`LocPinX = Width*0.5`). Дочірні фігури групи мають координати **відносно групи**.
- Масштаб: за замовчуванням використати той самий коефіцієнт, що й VSDX-**імпортер** draw.io (`mxVsdxUtils` у репозиторії jgraph/drawio: 40 px/см ⇒ 101.6 px/дюйм) **[ПІДТВЕРДЖЕНО в коді: `mxVsdxUtils.screenCoordinatesPerCm=40`, `CENTIMETERS_PER_INCHES=2.54`; той самий `CONVERSION_FACTOR` у `VsdxExport.js`; див. DECISIONS D-002]**. Тоді перевірка «туди й назад» через імпорт draw.io дасть ті самі розміри.
- Розмір сторінки Visio = bbox усіх елементів сторінки + поле. Або `pageWidth/pageHeight` з `mxGraphModel`, якщо діаграма їх використовує (опція).
- Обертання: `rotation` (градуси, за годинниковою стрілкою, Y вниз) → `Angle` у Visio (радіани, проти годинникової, Y вгору): знак змінюється. `flipH/flipV` → `FlipX/FlipY`.

## 6. Відповідність можливостей

### 6.1 Стилі (загальне)
Обов'язково врахувати **значення за замовчуванням draw.io**: відсутній ключ ≠ «нічого». Наприклад, у лінії за замовчуванням `endArrow=classic`, у фігури — білий фон і чорна обводка, шрифт Helvetica 12. Взяти значення з `default.xml` / `Graph.js` у репозиторії draw.io і зафіксувати в `style.py` з посиланням на джерело. Значення `none` / `default` / відсутність ключа розрізняти явно.

| draw.io | Visio | Примітка |
|---|---|---|
| `fillColor`, `fillOpacity`, `opacity` | `FillForegnd`, `FillForegndTrans` | `none` → `FillPattern=0` |
| `gradientColor`, `gradientDirection` | Fill gradient cells | спрощення допустиме → звіт |
| `strokeColor`, `strokeWidth`, `strokeOpacity` | `LineColor`, `LineWeight` (pt), `LineColorTrans` | `none` → `LinePattern=0` |
| `dashed`, `dashPattern` | `LinePattern` | найближчий стандартний патерн |
| `rounded`, `arcSize` | `Rounding` | |
| `shadow` | Shadow cells | можна пропустити → звіт |
| `rotation`, `flipH`, `flipV` | `Angle`, `FlipX`, `FlipY` | див. §5 |
| `fontFamily`, `fontSize`, `fontColor`, `fontStyle` (біти: 1 bold, 2 italic, 4 underline, 8 strikethrough) | розділ `Character` | розмір у pt **[VERIFY як Visio зберігає шрифт: за ім'ям чи через таблицю шрифтів]** |
| `align`, `verticalAlign`, `spacing*`, `whiteSpace=wrap` | `Paragraph.HorzAlign`, `VerticalAlign`, `LeftMargin`… | |
| `labelPosition`, `verticalLabelPosition` (підпис ззовні) | `TxtPinX/Y`, `TxtWidth/Height` (Text Transform) | |
| `html=1` підписи | `<Text>` з маркерами `<cp IX>`/`<pp IX>` + рядки Character/Paragraph | теги b/i/u/font/br/div/span-style; решта → чистий текст |
| `link` | розділ `Hyperlink` | |
| `tooltip` | `Comment` (або Shape Data) | |
| `<object>`/`<UserObject>` атрибути | розділ `Property` (Shape Data) | **дуже корисно**: дані пристроїв не губляться |
| `placeholders=1`, `%name%` | підставити значення під час конвертації | |

### 6.2 Фігури
- **Нативна геометрія (етап 1):** rectangle, rounded, ellipse, rhombus, triangle, hexagon, parallelogram, trapezoid, cylinder, cloud (наближення), process, document, text (без рамки), line/arrow-фігури. Кожна — функція, що будує рядки `Geometry` (`MoveTo/LineTo/ArcTo/EllipticalArcTo/RelCubBezTo`…) у відносних координатах фігури.
- **Зображення:** `shape=image;image=data:...` → вбудувати в `visio/media/`. `image=http(s)://...` → не завантажувати за замовчуванням: сіра заглушка + звіт (опція `--fetch-images`).
- **Таблиці** (`shape=table`, `tableRow`, `partialRectangle`) → група з прямокутників і тексту; складні випадки → fallback.
- **Усе інше** (стенсили `mxgraph.*`, у тому числі `mxgraph.cisco.*`, AWS, network тощо) → §6.4.

### 6.3 Лінії
- Лінія у Visio — 1-D фігура: `BeginX/BeginY/EndX/EndY` + `Geometry` з точок; проміжні точки — з `mxGeometry/Array` (waypoints) **після** обчислення реального маршруту.
- **Маршрут:** draw.io зберігає лише контрольні точки, а не фактичну ламану. Для `edgeStyle=orthogonalEdgeStyle|elbowEdgeStyle|entityRelationEdgeStyle` реальну ламану треба **обчислити** (портувати логіку `mxEdgeStyle`) або взяти з рендеру draw.io. Рекомендація: на старті простий ортогональний маршрутизатор за waypoints + exit/entry; порівнювати з SVG-експортом draw.io (там є реальні шляхи `<path>` ліній, які можна зіставити за id/порядком **[VERIFY, чи SVG-експорт дає зіставні id]**).
- `curved=1` → `RelCubBezTo`/NURBS або наближення ламаною → звіт.
- **Приклеювання:** елемент `<Connects>` на сторінці (`FromCell=BeginX/EndX`, `ToCell=PinX` для динамічного приклеювання, або `Connections.Xn` для фіксованої точки). Для `exitX/exitY/entryX/entryY` додати рядки в розділ `Connection` цільової фігури і клеїти до них.
- **Перемаршрутизація:** щоб Visio не «перемалював» лінії при відкритті, задати `ConFixedCode`/`ShapeRouteStyle`/`ConLineRouteExt` згідно з `--reroute` **[VERIFY значення на еталоні: Visio не повинен змінювати маршрут при відкритті, але лінія має слідувати за фігурою при перетягуванні]**.
- Стрілки: `startArrow/endArrow` + `startFill/endFill` + `startSize/endSize` → `BeginArrow/EndArrow` (індекси стандартних стрілок Visio) + `BeginArrowSize/EndArrowSize`. Таблицю відповідностей classic/block/open/oval/diamond/ERmany/ERone/… → номери Visio зробити окремим словником **[VERIFY номери на еталоні]**.
- Підписи ліній: дочірні cell'и з `relative=1` (x ∈ [-1,1] — позиція вздовж лінії, `mxPoint as="offset"` — зсув) і `value` самої лінії → текст лінії (`TxtPinX/Y` у локальних координатах 1-D фігури). Кілька підписів → основний на лінії, додаткові → окремі текстові фігури, згруповані або поруч → звіт.
- Лінія без source/target (вільна) → та сама 1-D фігура без `Connects`.

### 6.4 Фігури без нативного відповідника (стенсили, іконки)
Два режими:
- **`--icons image` (етап 4, за замовчуванням):** відрендерити фігуру **без підпису** через draw.io CLI в PNG (або SVG) свого розміру. Вбудувати як `Foreign`-фігуру (`ForeignData` + rel на `visio/media/imageN.png`). Підпис — окремим текстом цієї ж фігури (щоб редагувався), позиція — згідно з `labelPosition`.
  - **Кеш:** ключ = hash(нормалізований стиль без текстових ключів + w + h). Однакові іконки рендеряться один раз — у мережевих схемах це основна економія.
  - **Пакетний рендер:** не запускати Electron на кожну іконку. Зібрати всі унікальні фігури в один тимчасовий `.drawio`, кожну на окремій сторінці, і експортувати сторінки циклом з `--page-index`, або все одним SVG з подальшим розрізанням **[вибрати швидший варіант після заміру]**.
- **`--icons vector` (етап 6, опційно):** стенсили draw.io — це XML (`<shape><foreground><path><move/><line/><curve/><arc/>…`), їх можна перетворити на розділи `Geometry` Visio, тобто векторні фігури, що редагуються. Багатоколірні іконки → група з підфігур (по одній на кожен fill/stroke-блок). Джерело стенсилів — `src/main/webapp/stencils/*.xml` у репозиторії draw.io (частина стиснута). Якщо стенсил не знайдено → fallback на image.
- **Майбутнє розширення (не зараз):** YAML-мапа `shape=mxgraph.cisco.routers.router → master з .vssx`, для тих, хто має бібліотеки Visio.

### 6.5 Структура документа
| draw.io | Visio |
|---|---|
| кілька `<diagram>` | кілька сторінок (`pages.xml` + `pageN.xml`), назви збережено |
| шари (дочірні до root, крім першого) | шари Visio (розділ `Layer` у PageSheet + `LayerMember` у фігур) **[VERIFY]** |
| `style=group` | група (`Type="Group"`) без власної геометрії |
| `container=1`, `swimlane` | група з фоновою фігурою; swimlane → заголовок + тіло. Нативні контейнери Visio (Container) — не на старті |
| `collapsed=1` | розгорнути (показати вміст) → звіт |
| `visible=0` | пропустити або прихований шар → звіт |
| фон сторінки (`background`) | фон сторінки / фонова фігура |

## 7. Перевірка (головне)

Ручна перевірка у Visio — найдорожчий ресурс, тому автоматичні перевірки мають ловити все, що можуть.

### 7.1 Автоматичні (у pytest, на кожній фікстурі)
1. **Структура пакета:** zip відкривається; кожен XML well-formed; кожен `r:id` резолвиться; кожен part є в `[Content_Types].xml`; ID фігур унікальні; кожен `Connect` вказує на наявні фігури.
2. **Відповідність схемі:** якщо знайдеться XSD для VSDX (специфікація [MS-VSDX]) — валідувати **[VERIFY наявність придатної XSD]**.
3. **Рендер LibreOffice:** `soffice --headless --convert-to png out.vsdx` має не падати. PNG порівнюється з PNG оригіналу з `drawio -x -f png` (SSIM або частка відмінних пікселів, поріг на фікстуру). LibreOffice прощає більше, ніж Visio, тому це перевірка «грубих» помилок.
4. **Туди й назад через draw.io:** `drawio -x -f png out.vsdx` (draw.io імпортує `.vsdx`) → порівняти з оригіналом. Другий незалежний рендерер.
5. **Порівняння з оракулом:** для синтетичних фікстур порівняти наш XML (ключові клітинки: XForm, Line, Fill, Connects, Geometry) з експортом draw.io v26.0.16. Відмінності — не обов'язково помилки, але привід подивитися.
6. **Порівняння з еталонами Visio:** для фікстур, що відтворюють еталонні файли автора, порівнювати структуру з тим, як це записав **сам Visio**. Це головне джерело правди для всього, що позначено [VERIFY].

### 7.2 Ручні (автор, Visio web), чекліст на кожну реальну топологію
- [ ] Файл відкривається **без** повідомлення про відновлення або помилку.
- [ ] Розміщення фігур і розмір сторінки — як в оригіналі.
- [ ] Текст читається, шрифт/розмір/жирність — приблизно як в оригіналі; текст редагується.
- [ ] Іконки на місці, не розмиті при 100–200 % масштабі.
- [ ] Лінії: стрілки правильні; при перетягуванні фігури лінія **йде за нею**.
- [ ] Маршрути ліній не змінились при відкритті.
- [ ] Підписи ліній на місці.
- [ ] Сторінки й назви сторінок — як в оригіналі.
- [ ] Shape Data (якщо були атрибути) — видно у властивостях фігури.

Результат автор повертає скріншотом або коротким списком розбіжностей. Кожна знайдена вада → нова синтетична фікстура + автотест, щоб вона не повернулася.

## 8. Що потрібно від автора (одноразово, до або на початку етапу 1)

1. **`template/blank.vsdx`** — порожня діаграма, створена у Visio web і завантажена.
2. **Еталонні `.vsdx`, намальовані у Visio web вручну** (маленькі, по 3–6 фігур):
   - `ref-basic.vsdx`: прямокутник, заокруглений прямокутник, еліпс, ромб; різні заливки й обводки; текст різного розміру, жирний і курсив; один текст у кілька рядків.
   - `ref-connectors.vsdx`: дві фігури + пряма лінія, приклеєна до обох; ортогональна лінія з двома згинами; лінія, приклеєна до конкретної точки з'єднання; різні стрілки на кінцях; підпис на лінії; пунктирна лінія.
   - `ref-structure.vsdx`: група з двох фігур; контейнер із фігурою всередині; **дві сторінки** з назвами; (за можливості) два шари.
   - `ref-image.vsdx`: вставлена PNG-картинка і **вставлена SVG-картинка** — щоб побачити, як Visio зберігає SVG.
   - `ref-data.vsdx`: фігура з 2–3 полями Shape Data і гіперпосиланням.
3. **Реальні топології:** 3–5 `.drawio`, що їх треба конвертувати (можуть бути приватні — тоді в `tests/fixtures/real/` під `.gitignore`).
4. Готовність відкрити згенерований файл у Visio web і дати фідбек за чеклістом §7.2 наприкінці кожного етапу.

## 10. Відомі підводні камені

- **Значення за замовчуванням draw.io** (§6.1) — найчастіше джерело «чому стрілка зникла / заливка чорна».
- **Відносні координати** в групах і контейнерах — в обох форматах, але відносно різних точок (лівий верхній кут проти Pin і Y вгору).
- **Лінії, приклеєні до фігур усередині груп**, — `Connect` має вказувати на внутрішню фігуру, а не на групу.
- **Фактичний маршрут ортогональної лінії** не зберігається в `.drawio`, його треба обчислити (§6.3).
- **HTML у підписах**: `&nbsp;`, `<br>`, вкладені `<div>`, `font-size` у px проти pt.
- **Visio web суворіший за LibreOffice**: файл, що відкривається в LibreOffice, у Visio може вимагати відновлення. Тому еталони Visio — головне джерело правди.
- **ID**: Visio-ID фігур — цілі числа, унікальні на сторінці; ID draw.io — рядки. Тримати мапу id → ID.
- **Юнікод/кирилиця** в тексті й назвах сторінок — перевіряти окремою фікстурою.
- **Windows (робоча ОС):**
  - кодування за замовчуванням там не UTF-8 (cp1251/cp1252): **кожен** `open()`, `read_text()`, `subprocess` — з явним `encoding="utf-8"`; XML писати байтами через `lxml`;
  - кирилиця і пробіли в шляхах (`C:\Users\Назар\Документи\схема 1.drawio`) — окрема фікстура в CI на Windows;
  - тільки `pathlib`, жодних жорстко прописаних `/` чи `/tmp`; тимчасові файли — через `tempfile`;
  - `subprocess` — завжди списком аргументів, без `shell=True`, з таймаутом. draw.io на Windows — GUI-застосунок (Electron), тож перевіряти код виходу **і** наявність вихідного файлу;
  - обмеження довжини шляху 260 символів — тримати тимчасові теки короткими;
  - файл `.vsdx`, відкритий у Visio, заблокований для запису → зрозуміла помилка, а не трасування стеку.
- **Ліцензія:** якщо переносити логіку з `VsdxExport.js` / `mxVsdxCanvas2D.js` / `mxEdgeStyle` (jgraph/drawio, Apache 2.0) — зберегти NOTICE і вказати джерело в коді.
