# drawio2vsdx

Convert [draw.io](https://www.drawio.com/) diagrams to Microsoft Visio `.vsdx` files that open in Visio (web and desktop) without repair prompts and stay editable.

> **Status: stage 0 (skeleton).** Pages (names, sizes, multiple pages) are written; shapes, connectors and text are **not converted yet** and are listed in the report. See [docs/BRIEF.md](docs/BRIEF.md) §9 for the roadmap.

## Install

Python 3.11+ is required (Windows, Linux, macOS). The only runtime dependency is `lxml`.

```
pipx install git+https://github.com/IsNazarii/drawio2vsdx
```

A standalone `drawio2vsdx.exe` for Windows (no Python needed) is built by CI and will be published in Releases.

## Usage

```
drawio2vsdx INPUT [-o OUTPUT] [options]
```

| option | meaning |
|---|---|
| `INPUT` | `.drawio`, `.xml`, `.drawio.svg`, `.drawio.png` (with embedded diagram) or a folder |
| `-o, --output` | `.vsdx` file or output folder (default: next to the input) |
| `-r, --recursive` | process folders recursively |
| `--pages` | `all` (default), `1,3`, `2-4`, or page names |
| `--scale` | pixels per inch (default 101.6, same as draw.io's VSDX importer) |
| `--page-size` | use draw.io page size instead of content bounds |
| `--template` | blank `.vsdx` saved by Visio to use as package template |
| `--report` | write a `.json` or `.md` report of everything simplified or lost |
| `--strict` | fail instead of warning on unsupported elements |
| `--strict-warnings` | exit code 2 if anything was simplified |
| `-v` / `-q` | verbose / quiet |

Exit codes: `0` success, `1` error, `2` success with warnings (only with `--strict-warnings`).

Check a produced file's package structure: `python -m drawio2vsdx.validate out.vsdx`.

## Development

```
python -m venv .venv && .venv/bin/pip install -e ".[dev]"
pytest
```

Render tests need draw.io Desktop and LibreOffice; without them they are skipped. On Ubuntu without root:

```
scripts/setup-dev-tools.sh          # draw.io (current + v26.0.16 oracle) and LibreOffice into ~/tools
pytest -m render -rs
python scripts/make_oracle.py       # draw.io v26.0.16 VSDX export of the fixtures -> tests/oracle/
```

Synthetic fixtures are generated by `python tests/fixtures/make_fixtures.py`. Private real topologies go into `tests/fixtures/real/` (git-ignored) and are picked up by the tests automatically.

Design notes and verified facts: [docs/DECISIONS.md](docs/DECISIONS.md).
